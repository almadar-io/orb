# Internationalization (i18n)

Orb programs can be written in your own language. Keywords, effect verbs, operators, type names,
tags, annotations and sigils all have Arabic and Slovenian spellings; the compiler canonicalizes them
before any later phase runs, so everything downstream — validation, codegen, the runtime — only ever
sees one English vocabulary. The file extension does not change.

**Identifiers are always yours.** Orbital, trait, entity, state, event and field names, collection
names, string literals and pattern props pass through untouched, in whatever script you wrote them.
A name that happens to spell a keyword is still a name: the compiler recognizes a keyword only where
the grammar expects one, never by text replacement.

Every code sample on this site carries **العربية** and **Slovenščina** tabs — the rendering is
produced by the same vocabulary tables the compiler uses, so what you see is a program that actually
compiles, not an illustration.

## Example

```lolo
app TaskApp "1.0.0"

orbital TaskManager {
  entity Task [persistent: tasks] {
    id : string!
    title : string
    completed : boolean = false
  }
  trait TaskBrowser -> Task [interaction] {
    initial: active
    state active {
      INIT -> active
        (fetch Task)
        (render-ui main { type: "entity-table", entity: "Task", fields: ["title", "completed"], itemActions: [{ event: "COMPLETE", label: "Complete" }] })
      COMPLETE -> active
        (set @entity.completed true)
    }
  }
  page "/tasks" -> TaskBrowser
}
```

Switch the tab and note what does **not** change: `TaskApp`, `TaskManager`, `Task`, `tasks`,
`TaskBrowser`, `active`, `COMPLETE`, `title`, `completed`, and every key inside the `render-ui`
object. Those are the author's, and a pattern prop is opaque to the translator by design.

That last rule has one visible consequence worth knowing. An operator written as an s-expression —
`(str/upper @entity.title)` — is vocabulary and translates. The same operator written as a quoted
string inside a pattern prop — `value: ["array/len", "@entity"]` — is a string, and strings are
never touched, so it stays English. Both compile identically; English spellings are valid in every
language.

## How the language is chosen

Deterministically, from the first thing the file says — never by scanning for familiar words.

- **`.lolo`** — the first token. If it equals one language's spelling of a top-level keyword
  (`app`, `uses`, `expects`, `type`, `theme`, `orbital`), that is the file's language; English
  otherwise.
- **`.orb`** — a top-level key equal to one language's spelling of `orbitals`.

English spellings are accepted in every language, because each lookup matches the English word before
consulting the translation table. So a file can be mostly Arabic and still say `Event` where Arabic
has no distinct word for it (see the Shapes table below).

## Command line

```bash
orb i18n vocab --json                  # dump the full vocabulary, every language
orb i18n check                         # coverage of the baked tables, exit 1 on problems
```

The compiler READS every language — writing a program in Arabic or Slovenian and compiling it
works today. Rendering an English program back out into another language is, for now, something the
documentation does rather than the CLI: the tabs above are produced in the browser.

### A note on the Arabic shape names

Arabic has no letter case, so the `entity` **keyword** and the `Entity` **shape** would be the same
word — and the compiler resolves that word to the keyword. Rather than emit a program that means
something other than what it says, the translator leaves those five shape names in English, which
every language accepts. Tracked as `G-i18n-1`.
